# @bubstack/moe-relay

Forward lifecycle events between coding-agent sessions. The controller hears that
the worker finished; nobody polls.

**Status:** imported, complete. 214 tests passing across 19 suites; 8 more in 2
suites skip themselves without a local `redis`. Nothing was left out of the
import. One thing stays open by design: the event schema is at `v2` and still
accepts `v1`.

Ships as the **`moe-relay`** plugin. `@bubstack/moe-mint` generates it into
`/plugins/moe-relay` from `packages/relay/mint/moe-relay.yaml`. Edit the YAML and
regenerate; never hand-edit the generated manifest.

Bin name: `moe-relay`.

## What it does

A worker session emits a lifecycle event — it started, it finished, it failed.
The relay carries that event to the controller session, which acts on it the
moment it lands. The controller runs no poll loop and reads no worker transcript.

Transport is a local unix socket. Runs spanning more than one host use the
optional redis transport, which carries the same events under the same schema.

## The event schema

The schema is versioned and currently at `v2`. `v1` events are still accepted.
Support for `v1` ends once no worker emits it.

## Tests

214 pass across 19 suites. A further 8 tests in 2 suites skip themselves when no
local `redis` is running; start `redis` and they run.

## What we got wrong

**`relay → tab` is REFUTED.** Going in, we expected a dependency edge, because we
assumed the relay would attribute per-session cost. It does not. The relay never
reads token usage at all, and `tab` is not a dependency. The edge is not missing
or deferred — it was never there, and the next reader should stop re-deriving it.
