# @bubstack/moe-relay

Forward lifecycle events between coding-agent sessions. A worker finishes; the controller hears it, and never polls.

Bin: `moe-relay`.

**Status:** imported, complete — nothing was left out. 214 tests pass across 19 suites; 8 more in 2 suites skip themselves when no local `redis` is running. The schema still carries `v1` alongside `v2`, and that deprecation is the one piece of work outstanding.

Ships as the **`moe-relay`** plugin. `@bubstack/moe-mint` generates it into `/plugins/moe-relay` from `packages/relay/mint/moe-relay.yaml`. Edit the yaml and regenerate; never hand-edit the generated manifest.

## What it does

Workers emit lifecycle events. The relay forwards each one to the controller session, which learns that a worker finished the moment the worker finishes. That is the whole job: the controller spends no turns asking.

## Transport

Events travel over a local unix socket. A run spread across several hosts uses the optional redis transport instead, which you supply and run yourself.

## Event schema

The schema is versioned and currently sits at `v2`. The relay still accepts `v1` events. Support for them ends once no worker emits `v1`.

## What it does not do

**`relay → tab` is REFUTED.** We expected that dependency edge, because we assumed the relay would attribute cost per session. It does not. The relay never reads token usage at all, and `tab` is not a dependency. We were wrong going in, and this line exists so the next reader stops where we did.
