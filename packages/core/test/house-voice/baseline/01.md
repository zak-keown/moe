# @bubstack/moe-relay

Forwards lifecycle events between coding-agent sessions, so a controller session
learns that a worker session finished without polling it.

Ships one binary, `moe-relay`.

## How it works

A worker session emits lifecycle events. The relay carries them to the sessions
that care. A controller waits on the relay instead of asking each worker whether
it is done yet.

The default transport is a local unix socket. For runs that span more than one
host, an optional redis transport replaces it.

## Event schema

Events carry a schema version, currently `v2`. The relay also accepts `v1`
events. Support for `v1` ends once no worker emits them.

## Plugin generation

This package ships as a plugin. `@bubstack/moe-mint` generates it into
`/plugins/moe-relay` from `packages/relay/mint/moe-relay.yaml`.

Edit the yaml. Never hand-edit the generated manifest.

## Tests

214 tests pass across 19 suites. A further 8 tests in 2 suites skip themselves
when no local `redis` is running; start redis to exercise them.

## Provenance

Hard-forked from the upstream repo `session-relay` at commit `a3f91c2`, dated
2026-07-14. Upstream is MIT licensed, and this package retains upstream's
`LICENSE` verbatim.

The import is complete. It left nothing out.

## One correction

We expected `relay → tab` to be a dependency edge, because we assumed the relay
would attribute cost per session. We were wrong. The relay never reads token
usage, and `tab` is not a dependency. Drop that assumption if you are carrying
it.
