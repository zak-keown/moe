# v0.2.0 Release Baseline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make six public packages, generated artifacts, and Memory recovery contracts describe the real `0.2.0`/`0.1.4` release boundary.

**Architecture:** Package manifests and package-local Mint YAML remain the version authorities; `pnpm mint` owns all generated output. Memory's rollback code receives a single released-predecessor constant and uses actual `0.1.4` package bytes to build hash-bound recovery capsules.

**Tech Stack:** Node 24 ESM, TypeScript, Vitest, pnpm, npm registry tarballs.

**Spec:** `docs/moe/specs/2026-09-04-v0.2.0-release-closure-design.md`

## Global Constraints

- All six public package and Mint versions are `0.2.0`.
- Generated `plugins/`, marketplace, and catalog output are changed only through `pnpm mint`.
- Memory recovery starts from the published `@bubstack/moe-memory@0.1.4` tarball, never a synthetic `0.1.5` artifact.
- Node 24 is the only native qualification lane; Windows remains database-asset smoke only.
- Production skill helpers remain dependency-free Node 24 ESM.

## Open Decisions

None. The approved release design fixes versions, release predecessor, and Node floor.

## Not Yet Specified

Protected-environment reviewers and npm trusted-publisher configuration are external setup for the final plan.

## Out of Scope

- Publishing an npm package or release asset.
- Making native Windows a Memory runtime target.
