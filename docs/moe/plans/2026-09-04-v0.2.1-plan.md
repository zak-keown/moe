# v0.2.1 release plan — make the install real (packaging P1) + cleanup

**Goal:** ship a patch that fixes what is broken today. **Priority 1 is
packaging:** 0.2.0 is shipping *without* the release-orchestration wiring, so its
published install is incomplete (raw-workspace tarballs — no top-level plugin
manifest, no LICENSE — so the `using-moe` bootstrap never registers). 0.2.1 wires
the orchestration and republishes complete plugin trees. Then: the
reproducibility fixes and low-severity backlog follow-ups, and a dead-code +
doc-truthing sweep from the promise-hunt audit.

> **Status (this session):** packaging was briefly demoted to "verify only" on
> the assumption 0.2.0 would wire the release `--execute` paths. Per the release
> owner, **0.2.0 ships before that wiring lands**, so packaging escalates to
> 0.2.1 **priority 1** (Track 1, `BL-d932811282`).

**Baseline:** `main` @ `64304930`; assumes `v0.2.0` has shipped (six public
packages at `0.2.0`). Authored 2026-09-04. See
[roadmap](./2026-09-04-release-roadmap-0.2.1-0.3.0.md) for the split rule and
inputs.

**Conventions:** every SKILL.md / hook / manifest change is mirrored into
`/plugins/` by `pnpm mint` — never hand-edit `/plugins/`. Gate each change with
`pnpm check` and `pnpm mint:check`; packaging changes also need
`pnpm provenance`.

## Track 1 — Packaging & install integrity (PRIORITY 1)

### P — Wire the release orchestration so installs carry the manifest + LICENSE  ·  size M  ·  **0.2.1 P1**  ·  `BL-d932811282`

0.2.0 ships without the release `--execute` wiring, so its published install is
the incomplete one: the raw-workspace tarball with no top-level
`.claude-plugin/plugin.json` and no LICENSE → the harness never registers the
`using-moe` SessionStart bootstrap, and the Apache-2.0 §4(b) notice is absent.
That is the worst user-facing state in the release, so it leads 0.2.1.

The machinery is already correct — it just isn't invoked (verified `main`):
- `release/candidate.ts` `prepareCandidate` packs `artifact.artifactRoot`, which
  `artifact/check.ts` sets to `plugins/<id>` — the **complete** generated tree
  (`.claude-plugin/plugin.json`, LICENSE, NOTICE, `dist`, all 8 harness dirs;
  `license-payload.ts` writes LICENSE/NOTICE there).
- `publish.yml` already calls `mint release candidate --execute`, but
  `release candidate/promote/certify-claude --execute` throw `*_EXECUTE_NOT_WIRED`.

**The work:** wire the three `--execute` paths to `prepareCandidate` /
`promoteToStable` / `runClaudeMaintenance`, then cut a `v0.2.1` that republishes
complete plugin trees. **Acceptance:** a published 0.2.1 tarball for every
publishable plugin contains `.claude-plugin/plugin.json`, the reachable
SessionStart bootstrap, LICENSE and NOTICE — for all eight harness manifest sets
(`artifact/check.ts` already asserts file presence); `pnpm provenance` green.
**Residual (→ 0.3.0):** an end-to-end "after install the bootstrap fires" test
for the non-memory plugins, under robust e2e testing (`BL-3ce1956bb4`).

## Sequencing

1. **P (packaging, PRIORITY 1)** — wire the three release `--execute` paths and
   cut a `v0.2.1` that republishes complete plugin trees. Everything else in
   0.2.1 rides on that republish, so it goes first.
