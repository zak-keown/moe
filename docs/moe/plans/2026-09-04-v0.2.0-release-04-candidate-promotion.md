# v0.2.0 Candidate and Promotion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify the release system from a clean checkout, then publish and promote the exact qualified `v0.2.0` artifacts through protected CI.

**Architecture:** Repository gates prove the source and generated artifacts before a candidate tag exists. Protected candidate CI produces `v0.2.0-rc.1`; host reports attach to those assets. A separately approved stable operation verifies all candidate records before moving the same six versions to `latest`.

**Tech Stack:** pnpm, GitHub Actions, npm trusted publishing/OIDC, GitHub releases.

**Spec:** `docs/moe/specs/2026-09-04-v0.2.0-release-closure-design.md`

## Global Constraints

- Do not run an external mutation without explicit user approval at that point.
- Candidate uses `next`; stable promotion uses the exact candidate bytes and `latest`.
- A failed preflight, missing qualification record, or hash mismatch stops the release.
- Local `--execute` remains a refusal path.

### Task 1: Run the complete local release-input gate

**Files:**
- Verify: `package.json`, `plugins/`, `NOTICE`, `docs/moe/generated/plugin-catalog.md`

**Interfaces:**
- Consumes: completed baseline, orchestration, and qualification plans.
- Produces: a recorded clean-checkout gate result for the candidate source SHA.

- [ ] **Step 1: Start from a clean checkout at the intended candidate SHA**

Run: `git status --short`

Expected: no unrelated changes; otherwise stop and isolate the release SHA.

- [ ] **Step 2: Run repository and artifact gates**

Run: `pnpm check && pnpm mint:check && pnpm artifact:check && pnpm provenance`

Expected: all commands exit 0.

- [ ] **Step 3: Run focused release contract tests**

Run: `pnpm --filter @bubstack/moe-mint exec vitest run test/release-*.test.ts test/cli.test.ts && pnpm --filter @bubstack/moe-memory test`

Expected: exit 0, including 0.1.4 recovery and Node 24 evidence assertions.

- [ ] **Step 4: Record the source SHA and commit any source-only release documentation**

```bash
git add ARCHITECTURE.md README.md docs/moe/plans docs/moe/specs
git commit -m "docs: prepare v0.2.0 release evidence"
```

Only commit files that changed for the release; do not create an empty commit.

### Task 2: Prove plan-mode release behavior is safe

**Files:**
- Verify: `packages/mint/dist/cli.js`, `packages/mint/test/cli.test.ts`

**Interfaces:**
- Consumes: CI guard and candidate/promotion executors.
- Produces: recorded proof that local planning works and local mutation refuses.

- [ ] **Step 1: Run candidate and promotion plan modes**

Run: `node packages/mint/dist/cli.js release candidate --tag v0.2.0-rc.1 --repo . && node packages/mint/dist/cli.js release promote --tag v0.2.0 --repo .`

Expected: each prints its plan without mutating npm or GitHub.

- [ ] **Step 2: Run a local mutation refusal**

Run: `node packages/mint/dist/cli.js release candidate --tag v0.2.0-rc.1 --repo . --execute`

Expected: non-zero with the CI-only guard diagnostic; no network mutation occurs.

- [ ] **Step 3: Preserve the command output in the release record**

Write a redacted release note containing candidate SHA, intended tags, and the refusal diagnostic. Do not write secrets or tokens.

### Task 3: Create and qualify the protected candidate

**Blocked by:** D1

**Files:**
- External output: GitHub prerelease `v0.2.0-rc.1`, six `0.2.0` npm versions under `next`, lock/catalog/checksum/inventory assets, qualification reports.

**Interfaces:**
- Consumes: candidate workflow and source SHA from Task 1.
- Produces: a candidate whose exact artifact hashes satisfy stable-promotion inputs.

- [ ] **Step 1: Request explicit user approval to create the candidate tag and dispatch protected candidate CI**

State the immutable source SHA, `v0.2.0-rc.1` tag, six `next` versions, and expected external mutations. Stop if approval is not given.

- [ ] **Step 2: Create and push the candidate tag after approval**

Run: `git tag -a v0.2.0-rc.1 -m "Moe v0.2.0 release candidate" <approved-sha> && git push origin v0.2.0-rc.1`

Expected: protected candidate workflow begins; do not retry by rebuilding locally.

- [ ] **Step 3: Verify candidate assets and registry records**

Confirm the draft/prerelease catalog, lock, checksums, six tarballs, inventories, npm `next` integrity, four recovery capsules, and matching source SHA. Any mismatch stops promotion.

- [ ] **Step 4: Dispatch host qualification by candidate tag**

Confirm successful Claude and Codex macOS/Linux reports, Copilot custom-path report, Node 24 Memory reports, and 0.1.4 migration/rollback evidence are attached to the candidate release.

### Task 4: Promote the verified stable release

**Blocked by:** D1

**Files:**
- External output: GitHub stable release `v0.2.0`, complete stable catalog, six npm `latest` tags.

**Interfaces:**
- Consumes: complete candidate assets and qualification evidence.
- Produces: stable `v0.2.0` whose catalog records the same hashes as `v0.2.0-rc.1`.

- [ ] **Step 1: Request explicit user approval for stable promotion**

Present candidate tag, source SHA, six artifact hashes, qualification summary, and the exact `latest` tag mutations. Stop without approval.

- [ ] **Step 2: Create and push the stable tag after approval**

Run: `git tag -a v0.2.0 -m "Moe v0.2.0" <approved-sha> && git push origin v0.2.0`

Expected: the protected stable workflow verifies candidate assets and performs no build, mint, pack, or npm publish.

- [ ] **Step 3: Verify the stable catalog and registry**

Run the release verify command against `v0.2.0`; confirm all six `latest` versions are `0.2.0`, every stable asset hash matches candidate, and all required reports validate.

- [ ] **Step 4: Record completed release state**

Update the release manifest with the actual commit ranges and archive/supersede the stale `0.1.x` release-plan claims. Commit only repository documentation and manifest state; external artifacts remain on npm and GitHub.
