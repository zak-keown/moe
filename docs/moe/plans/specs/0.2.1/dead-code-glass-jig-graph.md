# Dead-code removal: glass chrome-ws bin + jig-graph traceCalls/CallResult

Backlog: BL-7394064152, BL-a959e92b57 — Size: XS

Two independent, removal-only source edits for the v0.2.1 patch. Both findings
were verified against main @ 64304930 and **still hold**. Neither package is a
`pnpm mint` input, so `/plugins/` does not regenerate.

---

## Problem

### BL-7394064152 — glass `browsing-compat` declares a `chrome-ws` bin pointing at a missing path

`packages/glass/browsing-compat/package.json` (source) declares:

```json
"bin": {
  "chrome-ws": "./scripts/chrome-ws.mjs"
}
```

There is no `scripts/` directory under `browsing-compat/`. The real executable
is `packages/glass/browsing-compat/chrome-ws` (extensionless, mode 0755). So the
bin target `./scripts/chrome-ws.mjs` resolves to nothing.

Impact is nil, confirmed on three counts:

- **Not a workspace member.** `pnpm-workspace.yaml` globs are `packages/*`,
  `packages/flight/ui`, `packages/flight/dashboard`,
  `packages/tab/bindings/typescript`. `packages/glass/browsing-compat` matches
  none, so it is never linked and its bin is never written to any
  `node_modules/.bin`. (`pnpm -r list` shows no package named `chrome-ws`.)
- **Not published.** The bin lives in the package `chrome-ws@1.0.0`, which ships
  nowhere; and the enclosing `@bubstack/moe-glass` tarball only includes
  `files: ["dist", "agents", "skills"]` — `browsing-compat/` is excluded.
- **Not minted.** `packages/glass/mint/moe-glass.yaml` mints only `dist` (payload)
  plus `skills/` and `agents/` (default components). The shipped browsing CLI is
  `packages/glass/skills/browsing/scripts/chrome-ws.mjs`, a separate `.mjs` tree;
  `browsing-compat/` is not referenced by the mint config.

Note mint *does* validate bin references — `validateExactFileReference(manifest.bin, 'bin', artifactPaths)`
in `packages/mint/src/package-manifest.ts` — which is why the generated
`/plugins/*/package.json` bins are correct. `browsing-compat/package.json`
escapes that validation precisely because it is not a mint input.

**`browsing-compat/` is NOT dead code and must not be deleted.** It is the live
CommonJS test-fixture tree for the entire glass suite: ~40 test files
`require('../browsing-compat/lib/*.js')` / `require('../browsing-compat/chrome-ws-lib.js')`
(e.g. `packages/glass/test/lib/cookies.test.mjs`, `.../chrome-process.test.mjs`,
`packages/glass/test/smoke.test.mjs`). The dead thing is *only the `bin` key*.

### BL-a959e92b57 — jig-graph `traceCalls`/`CallResult` are exported but never called in production

`packages/jig-graph/src/moedex.ts` defines:

```ts
export interface CallResult {
  results: GraphResult[];
}
```
```ts
async traceCalls(symbol: string): Promise<CallResult> {
  return (await this.call("trace_calls", {
    query: symbol,
  })) as CallResult;
}
```

Verified real (non-test, non-`dist`) consumers of `MoedexClient`:

- `packages/jig-graph/src/seed.ts` calls `impactAnalysis`, `searchContext`,
  `traceConsumers`.
- `packages/jig-graph/src/validate.ts` calls `impactAnalysis`, `traceConsumers`.
- `packages/jig-graph/src/jig-extension.ts` calls `isAvailable`, `disconnect`.

**Nothing calls `traceCalls`.** `CallResult` is used only as that method's return
type — no other file imports it (`seed.ts` imports `GraphResult, MoedexClient`;
`validate.ts` imports `ConsumerResult, MoedexClient`).

The only surviving references are:
- `packages/jig-graph/test/seed.test.ts` — `traceCalls: vi.fn().mockResolvedValue({ results: [...] })` in `makeMockClient` (never asserted on).
- `packages/jig-graph/test/validate.test.ts` — `traceCalls: vi.fn().mockResolvedValue({ results: [] })` in `makeMockClient` (never asserted on).
- `packages/jig-graph/dist/moedex.js` and `dist/moedex.d.ts` — build artifacts, regenerated by `tsc -b`.

Removing the export breaks nothing external: jig-graph's public surface is
`exports: { "./jig-extension": "./dist/jig-extension.js" }`, and the only
cross-package consumer is `@bubstack/moe-jig-graph/jig-extension`, listed in
`EXTENSION_PACKAGES` in `packages/jig/src/extension.ts`. `moedex.ts` internals
are not part of that surface. jig-graph has no `mint/` directory and no
marketplace/registry entry — it is a library, not a minted plugin.

## Change

### 1. `packages/glass/browsing-compat/package.json` (source)

Delete the entire `bin` object. Keep every other field. The resulting file:

```json
{
  "name": "chrome-ws",
  "version": "1.0.0",
  "description": "Lightweight Chrome DevTools Protocol client for direct browser control - zero dependencies",
  "engines": {
    "node": ">=24"
  }
}
```

Do **not** delete the file. It has no `"type"` field, so it defaults to
CommonJS; that is the boundary marker that lets the glass tests `require()` the
`.js` fixtures even though the glass root `package.json` is `"type": "module"`.
Removing the file would flip those `.js` files to ESM and break the whole glass
suite.

### 2. `packages/jig-graph/src/moedex.ts` (source)

- Delete the `export interface CallResult { results: GraphResult[]; }` block.
- Delete the `async traceCalls(symbol: string): Promise<CallResult> { ... }`
  method.

Leave `impactAnalysis`, `traceConsumers`, `searchContext`, `connect`,
`disconnect`, `isAvailable`, `_setTransport`, and the `ImpactResult` /
`ConsumerResult` / `SearchResult` / `GraphResult` interfaces untouched.

### 3. `packages/jig-graph/test/seed.test.ts` (source, test)

Remove the stale mock property from `makeMockClient`:

```ts
    traceCalls: vi.fn().mockResolvedValue({
      results: [{ rel_path: "src/api/middleware.ts", score: 0.88, repo: "moe" }],
    }),
```

(The object is cast `as unknown as MoedexClient`, so leaving it would still
compile — but the removal keeps the mock honest and removes the last reference
to the deleted method.)

### 4. `packages/jig-graph/test/validate.test.ts` (source, test)

Remove the stale mock property from `makeMockClient`:

```ts
    traceCalls: vi.fn().mockResolvedValue({ results: [] }),
```

## Sequencing & dependencies

- The two edits are fully independent (glass vs. jig-graph, different packages)
  and can be done in parallel or as one small commit.
- Neither touches release code, so there is **no dependency on** the packaging
  wiring in BL-d932811282 (`mint release candidate --execute`).
- Both should land **before the v0.2.1 tag is cut**, so the republished tarballs
  reflect cleaned source. Concretely: jig-graph's `dist/moedex.{js,d.ts}` will be
  rebuilt without the dead symbols and republished by the v0.2.1 tag. (The glass
  change has zero tarball impact — `browsing-compat/` is excluded from the
  `@bubstack/moe-glass` package `files` — so it is pure repo hygiene with no
  release-ordering constraint.)

## Risks

- **Deleting `browsing-compat/package.json` (instead of just the `bin` key)**
  would remove the CommonJS boundary and break ~40 glass test files that
  `require()` the `.js` fixtures under glass's `"type": "module"` root. Only the
  `bin` field is removed.
- **Deleting the `browsing-compat/` directory** would break the entire glass
  suite — it is a live fixture tree, not dead code. The backlog title's "missing
  scripts/ dir" refers to the bin *target*, not the directory.
- **Stale dist**: ensure a build runs before the tag so `dist/moedex.{js,d.ts}`
  no longer carry `traceCalls`/`CallResult`. `pnpm check` compiles jig-graph
  transitively (turbo `build` is a `test` dependency), and the v0.2.1 candidate
  rebuilds from source, so this is covered by the normal gate + release path.
- Leaving the `traceCalls` mock lines in place would still compile (cast through
  `unknown`) but leaves a dangling reference to a deleted method — removed here
  for cleanliness; no behavior risk either way.
