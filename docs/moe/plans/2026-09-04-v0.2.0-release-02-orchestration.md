# v0.2.0 Release Orchestration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire Mint's tested release primitives into fail-closed, CI-only candidate and promotion operations.

**Architecture:** A CI guard verifies Actions identity, protected deployment, tag, SHA, and OIDC before creating production adapters. Candidate orchestration assembles and verifies six artifacts once, publishes exact tarballs to `next`, and records every candidate asset. Promotion reloads and validates those assets and evidence, then moves only the existing versions to `latest`.

**Tech Stack:** TypeScript, Node 24, GitHub Actions OIDC, npm trusted publishing, Vitest.

**Spec:** `docs/moe/specs/2026-09-04-v0.2.0-release-closure-design.md`

## Global Constraints

- Local `--execute` always refuses mutation.
- Candidate and stable execution require different protected environments.
- No publish, release upload, or dist-tag move begins before every read-only preflight passes.
- Promotion performs no build, mint, pack, or npm publish.

## Open Decisions

None.

## Not Yet Specified

The final protected-environment reviewer roster is repository administration, not source code.

## Out of Scope

- Running a real candidate or stable release.
