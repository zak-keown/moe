# v0.2.0 Release Qualification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make protected CI produce complete, candidate-hash-bound evidence for the required Node 24, host, Copilot, and Memory recovery qualification boundary.

**Architecture:** Qualification jobs download candidate assets from the release lock rather than accepting operator paths or digests. Target drivers install only candidate tarballs in isolated locations and emit redacted evidence records. Mint validates every required tuple before stable promotion can proceed.

**Tech Stack:** GitHub Actions, Node 24, TypeScript, Vitest, Claude Code, Codex, Copilot CLI.

**Spec:** `docs/moe/specs/2026-09-04-v0.2.0-release-closure-design.md`

## Global Constraints

- Claude Code and Codex each qualify on macOS and Linux.
- Copilot receives custom-path coverage, not a structural-only substitute.
- Jobs use candidate catalog/lock assets and secret-backed protected environments.
- Reports contain artifact hashes and redacted result records, never credentials or transcript prose.
- Node 22 has no release qualification lane.

## Open Decisions

None.

## Not Yet Specified

Exact protected-environment reviewers are configured outside the repository.

## Out of Scope

- Certifying preview-only harnesses.
- Running host qualification against workspace packages.
