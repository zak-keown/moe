# v0.3.0 release plan — features

**Goal:** the next capability release. Four tracks: the backlog's high/medium
features, the advertised-surface stubs made real, the multi-harness parity work,
and (stretch) the architecture extractions. Items marked **needs spec** get
their own design + plan-set before execution.

**Baseline:** builds on 0.2.1. Authored 2026-09-04 against `main` @ `64304930`.
See [roadmap](./2026-09-04-release-roadmap-0.2.1-0.3.0.md).

**Conventions:** SKILL.md / hook / manifest changes flow through `pnpm mint`
into `/plugins/`; gate with `pnpm check` + `pnpm mint:check`. New skills need a
tier entry in `packages/core/skill-tiers.yaml` (`authored:`, since the
`imported:` set is frozen) or `metadata.test.ts` goes red.

## Track 1 — Backlog features

### F1 — `moe-handoff` / `moe-resume` skill pair  ·  BL-0e876bea7e · high · size M
`moe-handoff` writes a `.continue-here` into `.moe/` capturing the state of Moe
itself; `moe-resume` picks it up and continues. The backlog v1.5 work (random
collision-free `BL-<hex>` ids, merge `f27827aa`) was the stated prerequisite for
a resume driver that fetches items by id — that blocker is cleared. This is the
flagship 0.3.0 feature: it turns the backlog into a session-spanning driver.
**Acceptance:** a handoff written in one session resumes cleanly in another,
including the active backlog item; works harness-neutrally.

### F2 — Robust e2e harness testing, incl. local models  ·  BL-3ce1956bb4 · high · **needs spec** · size L
Prove Moe works end-to-end on real harnesses, with local models where possible
("if Moe works on a local model, frontier models will sail"). This also pays
down the synthesis's biggest gap — *validation is structural, not behavioural*:
CI has never exercised the shipped artifact, crew's tmux suites, glass's Chrome
smoke, or any real model. A real operational scenario (the backlog suggests a
tic-tac-toe game) as a required check. **Depends on 0.2.1 P** — you can't
e2e-test an install that has no manifest. Scope the runner and the CI lanes in
its own spec.

### F3 — Wire review/fix skills to read & write the backlog  ·  BL-87732aad96 · medium · size M
v1.5 wired `fixing-a-code-review` as the first backlog producer. Extend the
pattern to the remaining review/fix skills (`reviewing-a-codebase`, etc.) so
findings land durably in `.moe/backlog/` instead of review-scoped reports that
die with the worktree. **Directly relevant:** the promise-hunt audit found 21 of
its 22 findings are *not* in the backlog — a wired `reviewing-a-codebase` would
have filed them. Consider filing this session's audit as the first real corpus.

### F4 — Project Manager module with pluggable backends  ·  BL-447808e572 · medium · **needs spec** · size L
Build off the backlog work; add a Shortcut integration as an optional non-local
backend. **Multi-harness constraint applies hard here** (CLAUDE.md): the backend
abstraction and any credential story must work for all eight harnesses, not just
Claude Code. Design the backend interface first.

### F5 — Hardener skill: adversarial self-test that files backlog items  ·  BL-a1008ef2d9 · medium · size M
Repo-local skill that does **not** install with Moe. Installs a temporary copy
of Moe and tries to break/compromise it; files backlog items for what it finds;
does not fix them. Pairs naturally with F3 (it needs a backlog to write to) and
with 0.2.1 P (a real install to attack). Authorized defensive self-testing —
scope it to a throwaway temp install.

## Track 2 — Advertised-surface stubs → real (promise-hunt audit)

### F6 — glass auto-capture console logging  ·  A#6 · size M
`browsing/scripts/lib/capture.mjs` always writes `# TODO: Console logging not
yet implemented`, yet `SKILL.md` promises a `{prefix}-console.txt` on every DOM
auto-capture. The interactive console API is *already built*
(`lib/console-logging.mjs`, `src/index.ts`). Wire auto-capture to the existing
CDP path (and the `browsing-compat` mirror). **Acceptance:** auto-capture emits
real console output; the stub string is gone.

### F7 — memory: Claude-side tool-result + `is_error` capture  ·  A#7 · size M
`src/parser.ts` discards every `tool_result` in the Claude parser (Codex matches
`call_id` fine) and hardcodes `is_error:false` everywhere; the schema/types/db
already carry the fields. Populate them Claude-side, then give `search.ts` a
consumer that uses error state (today it only counts tool names).

### F8 — flight video evidence  ·  A#8 · size M
`docs/format.md` documents a `video` evidence field; the writer records
screencast frames but never stitches them and no UI renders it
(`RunSummaryCard.tsx`). Either stitch frames → video + render, or remove the
documented field. Decide, don't leave it half-built.

### F9 — jig-graph `plan validate --manifest` + richer `seed`  ·  A#1, A#12 · size M
`--manifest <path>` is in `--help` but its body is `console.error("--manifest is
not yet implemented"); return 1`. Implement it (validate every plan a MANIFEST
lists). Separately, `seed.ts` emits `[TODO]` placeholders for every task
name/interface/step — the file clustering + `depends_on` are graph-derived and
real, so enrich the names/interfaces from the graph rather than emitting TODOs.

## Track 3 — Multi-harness parity (roadmap risk R2)

### H1 — Codex MCP emission + parity roadmap  ·  A#3, A#4, A#5, A#13 · **needs spec** · size L
`emitCodexMcp` (in the otherwise-orphaned `mint/adapters/mcp.ts`, see 0.2.1 A#2)
is a complete Codex MCP-config emitter that is never called;
`adapters/codex.ts` pushes `COMPONENT_OMITTED "mcp servers are not emitted for
codex in v1"`. Ship it — that makes memory/glass MCP reach Codex and resolves
the `docs/CODEX.md` ⇄ yaml contradiction (0.2.1 D2) at the code level, and
decides the fate of `mcp.ts` (become the single MCP-emit source, or delete).
Then the broader decision: the parity roadmap for commands/hooks/mcp/agents on
codex/kimi/opencode/pi (today skills-only on most). Close the
**bootstrap-without-backend** gap (A#4): `moe-memory.yaml` bootstraps
`remembering-conversations` on cursor/kimi/pi, which have no search backend and
whose skill never mentions the `moe-memory search` CLI fallback — either teach
the skill the CLI fallback or stop bootstrapping it where no backend exists.

### H2 — Multi-harness front door  ·  synthesis theme #1 · **needs spec** · size L
`bin/moe-install` runs only `claude plugin`; `bin/moe-doctor` probes only
`claude`; the kimi/pi/opencode/codex install docs point at the repo root while
manifests live in `plugins/<name>/`. "8 harnesses" is real inside mint and
imaginary at the front door. Make install + doctor harness-aware for the
preview-tier seven. **Depends on 0.2.1 P** (there must be a correct artifact to
install first).

## Track 4 — Architecture extractions (stretch / 0.3.x)

Named in the roadmap's "needs a spec" list; pull into 0.3.0 only if capacity
allows, each with its own design:

- **X1 — shared CDP transport/launcher/session package** (glass ⇄ flight
  divergent fork; `chrome-ws` third `WebSocketClient`; `bin/lib/probes.mjs`
  reinvents discovery). Extract transport/launcher/session/profile-lock; keep
  action layers separate.
- **X2 — shared harness-paths + usage/cost model.** `~/.claude/projects`
  encoding and `$CODEX_HOME/sessions` are re-known by memory/crew/flight/core;
  four cost surfaces with no shared model, and Claude JSONL (the one dialect a
  user has) is the one `tab` can't price.

## Sequencing

1. **F1** (handoff/resume) and **F3** (wire review/fix to backlog) first — they
   compound: F3 fills the backlog, F1 drives it, F5 feeds it.
2. **F6–F9** are independent, self-contained stub→real conversions — good
   parallel work once specs aren't needed.
3. **F2** and the **H1/H2** parity work depend on 0.2.1 **P** landing; spec them
   in parallel with track-2 execution.
4. **F4** (PM module) and the **X** extractions are the largest and need
   design — spec early, execute late.

## Explicitly deferred

- Native Windows as a runtime target (WSL2 remains the story).
- The `maka` / `openclaude` placeholder adapters (A#22) — unregistered skeletons;
  leave until their harnesses are real.
